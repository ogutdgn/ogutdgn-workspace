# Architecture

This document explains how the `ogutdgn-workspace` monorepo is put together — the
tech stack, how each site is built, how content flows, and how things deploy.

## Overview

The repo holds two independent websites that share tooling but not design:

- **`apps/portfolio`** → [ogutdgn.com](https://ogutdgn.com) — a minimal personal
  site (home, blog, projects) on the *astro-nano* aesthetic, with a custom
  cursor-following mascot.
- **`apps/tools`** → [tools.ogutdgn.com](https://tools.ogutdgn.com) — a dark/neon
  catalogue of small tools, some of which run in the browser as React islands.

Both are **static Astro sites**. All content is **local MDX** — there is no CMS,
database, or server at runtime. Each site builds to plain HTML/CSS/JS and is served
from Vercel's CDN.

> The sites were migrated from an earlier **Next.js + Sanity** stack. The Sanity
> content was exported once to MDX (see [Content migration](#content-migration));
> Sanity is no longer a runtime dependency of either app.

## Tech stack & why

| Concern | Choice | Rationale |
|---|---|---|
| Site framework | **Astro 6** | Ships zero JS by default; content collections + MDX fit a content site; islands allow React only where needed |
| Language | **TypeScript** | Type-safe content schemas (Zod) and components |
| Styling | **Tailwind CSS 3** (`@astrojs/tailwind`) | Utility-first; each app keeps its own theme tokens |
| Interactivity | **React 19** via `@astrojs/react` | Only on the tools site, hydrated as islands |
| Content | **MDX** content collections | Authored in-repo, validated at build time |
| Monorepo | **Turborepo** + **pnpm workspaces** | One install, cached task pipeline, two deployables |
| Hosting | **Vercel** (static) | One project per app, CDN-served output |

Runtime requirements: **Node ≥ 22.12** (Astro 6 / Vite 7), **pnpm**. A single
`pnpm.overrides.esbuild` pin in the root `package.json` keeps one esbuild version
across the workspace.

## Monorepo structure

```
apps/
  portfolio/   @ogutdgn/portfolio   — Astro static site
  tools/       @ogutdgn/tools       — Astro static site + React islands
packages/
  sanity-shared/                    — archived Sanity schemas/client/queries (unused by apps)
scripts/                            — one-time Sanity → MDX migration tooling + tests
turbo.json                          — task pipeline (build/dev/lint/type-check)
pnpm-workspace.yaml                 — workspace globs (apps/*, packages/*)
```

Each app exposes the same npm scripts (`dev`, `build`, `lint`, `preview`) so the
Turborepo pipeline treats them uniformly. `turbo build` fans out to both apps;
their output directory is `dist/`.

`packages/sanity-shared` is intentionally **kept as an archive** — it still contains
the old Sanity Studio schemas and queries, but neither app imports it. It can be
deleted if the Sanity project is ever fully retired.

## Portfolio app (`apps/portfolio`)

A content-first static site.

**Content collections** (`src/content.config.ts`, Zod-validated):

- `blog` — `src/content/blog/<slug>/index.mdx` (title, description, date, draft?)
- `projects` — `src/content/projects/<slug>/index.mdx` (+ demoURL?, repoURL?)

**Pages** (`src/pages/`):

- `index.astro` — intro + photo
- `blog/index.astro` (year-grouped) and `blog/[...id].astro`
- `projects/index.astro` and `projects/[...id].astro`
- `rss.xml.ts`, `robots.txt.ts`; sitemap via `@astrojs/sitemap`

**Design system** is ported from the *astro-nano* theme: a shared `PageLayout`,
`Container`, `Header` (with a persisted light/dark toggle), `Footer`, `ArrowCard`,
and prose styles. Inter/Lora fonts via `@fontsource`. `@vercel/analytics` is
included.

**The mascot** (`src/components/MiniDogan.astro`) is the one piece of bespoke
client JS. It adapts the *oneko* cursor-chase engine: a sprite sheet
(`public/mini-dogan.png`, generated by `scripts/generate-sprite.mjs`) composites a
real photo of the owner's face onto an animated pixel body. It chases the cursor
with directional run frames, performs a squash/stretch **jump** (with a shrinking
ground shadow and dust puffs) when idle, and ducks behind the navbar
(`z-index` below the sticky header). It respects `prefers-reduced-motion` and
attaches its cursor listener idempotently across view-transition navigations.

**Legacy redirects** (`vercel.json`): `/blogs → /blog`,
`/project/:slug → /projects/:slug`.

## Tools app (`apps/tools`)

Same Astro foundation, but with **interactive React islands** and its own
dark/neon design (custom Tailwind tokens: `void`, `surface`, `neon*`, plus
`grid-bg`/`noise`/`scan-line` utilities; Geist Sans/Mono fonts).

**Content collection** (`src/content.config.ts`):

- `tools` — `src/content/tools/<slug>/index.mdx`. Rich frontmatter: tagline,
  overview, `category`, `hostType` (`internal` | `external`), `toolType`,
  `status`, `featured`, links, `technologies`, `tags`, `icon`/`coverImage`/
  `screenshots`, `demoVideoUrl`, `publishedAt`. Tool images live under
  `public/tools/<slug>/` and are referenced by URL path so both Astro pages and
  React islands can use them.

**Islands vs static:**

- Static (Astro): the shell (`BaseLayout`, `Navbar`), the bespoke home layout, and
  the tool detail pages.
- Islands (React, hydrated):
  - **`FilterBar`** (`client:load`) — the filterable tool grid + slide-in
    **`ToolDrawer`**. The home page (`index.astro`) loads the collection, maps each
    entry to a serializable **`ToolMeta`** (`src/lib/tool.ts`), and passes the
    array to the island. External-tool drawer bodies are pre-rendered to HTML with
    `marked` server-side (so no Portable Text / markdown runtime ships to the
    island).
  - **Embedded tools** — runnable tools (e.g. `inter-arrival-sampler`) live in
    `src/tools/` and are listed in a `TOOL_COMPONENTS` registry. The detail page
    renders the matching one through a single `EmbeddedTool` wrapper island
    (`client:only="react"`) for reliable hydration.

**Routing:** `index.astro` (home) and `[...slug].astro` for **internal** tools
only (`getStaticPaths` filters `hostType === "internal"`). External tools appear
on the home grid and open via their `liveLink` or the drawer — they have no detail
page. Plus `robots.txt.ts` and a sitemap. URLs match the previous site, so no
redirects are needed.

## Content migration

Content was migrated once from Sanity to MDX. The tooling lives in `scripts/` and
is kept for reference (it is not part of any build):

- `portable-text-to-markdown.mjs` — a dependency-free Sanity Portable Text → Markdown
  converter, with `portable-text-to-markdown.test.mjs` (run via
  `node --test "scripts/*.test.mjs"`).
- `export-sanity.mjs` — exported the portfolio's blogs and projects.
- `export-tools.mjs` — exported the tools, resolving categories and downloading
  images.

Going forward, content is edited directly as MDX; these scripts are historical.

## Build & deploy

- `turbo build` builds both apps; each emits a static `dist/`.
- **Vercel:** two projects, one per app, each with **Root Directory** set to the
  app folder, **Framework Preset: Astro**, and static output. Vercel installs the
  whole pnpm workspace from the root lockfile, then builds the targeted app. No
  runtime env vars are needed (the sites are fully static).
- Content/UI changes deploy by pushing to the production branch; Vercel keeps the
  last successful deployment serving if a build fails.

## Conventions

- **Content** is MDX with Zod-validated frontmatter — invalid metadata fails the
  build rather than shipping.
- **Islands** receive only serializable props (strings, arrays, booleans,
  pre-rendered HTML strings) — never CMS objects or non-serializable values.
- **Commits** follow `type(scope): subject` (≤72 chars) with a body:
  a `What changed:` bullet list and a `Why:` line, plus `Tests:` / `Build:` notes
  when relevant. Scopes name the area (e.g. `portfolio`, `tools`, `mascot`,
  `content`, `pages`, `ui`, `design`, `export`, `repo`). Files are staged by
  explicit path.
